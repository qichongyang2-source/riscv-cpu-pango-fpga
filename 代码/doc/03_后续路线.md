# 03 后续路线（性能与高级任务）

赛题评分公式：

```
Score = CoreMark / total_time = (CoreMark / MHz) × 频率
```

即两条主线：**提高 CoreMark/MHz（IPC × 指令效率）** 与 **提高可综合频率**，
同时控制 LUT/FF/BRAM 资源。下面按收益/代价排序列出实施路线。

---

## 阶段 1：M 扩展（已完成）

MUL/MULH/MULHSU/MULHU 单拍完成，DIV/DIVU/REM/REMU 为 32 拍迭代。
后续可把除法改为提前结束（剩余被除数位为 0 时停止）或基 4 迭代，降低平均延迟。

### 原始分析（保留）

CoreMark 中含大量 32 位乘加与取模，软件模拟乘法会吃掉 30%～50% 的周期。

**实现建议**

| 运算 | 方案 | 代价 |
|---|---|---|
| `MUL/MULH/MULHSU/MULHU` | 1 拍 32×32 乘法器（DSP 或 LUT） | 1 个 DSP48 / ~500 LUT，关键路径 +2 ns |
| `DIV/DIVU/REM/REMU` | 33 拍恢复余数迭代，EX 级 stall | 一个 33 位减法器 + 状态机 |

- 译码：`funct7=0000001` 时识别为 M 扩展，否则非法指令。
- 除法器忙时拉高 `ex_stall`，冻结 IF/ID/EX，MEM/WB 继续流动。
- 需同步更新 `doc/02_验证报告.md` 的指令覆盖表。

**预期收益**：CoreMark/MHz +20%～40%。

---

## 阶段 2：分支预测（BTB + 两位计数器，已完成基础版）

已实现 64 项 BTB + 64 个两位饱和计数器，预测正确时不冲刷流水线。
后续增强：返回地址栈（RAS，加速函数返回）、更长的 BHT 历史、BTB 两路组相联。

### 原始设计（保留）

当前分支在 EX 解析，固定 2 拍惩罚；CoreMark 分支密度约 15%～20%。

**结构**

```
BTB: 64 项，index = pc[7:2]，tag = pc[31:8]
     表项 { valid, tag, target, 2-bit counter }
BHT: 与 BTB 同索引，2 位饱和计数器（00/01 强/弱不跳，10/11 弱/强跳）
```

- **IF 级预测**：查 BTB，命中且计数器 ≥ 10 则下一 PC 取 `target`，否则 `pc+4`。
- **EX 级校正**：实际方向/目标与预测不符时冲刷并更新 BTB/BHT。
- 进一步优化：把分支比较前移到 **ID 级**（增加 ID 级比较器 + 专用转发通路），
  预测失败只清 1 条指令。

**预期收益**：分支惩罚从 2 拍降到约 0.3～0.6 拍，CoreMark/MHz +15%～25%。

---

## 阶段 3：I/D Cache（基础版已完成，继续增强）

**已完成**：2 KB 两路组相联（伪 LRU）I/D Cache，行 4 字，命中零等待，
缺失整行填充；IMEM/DMEM 改为 BRAM 风格同步读，64 KB 可映射 BRAM。

**总线突发（已完成）**：IMEM/DMEM 改为 4096 x 128 位（16 字节使能写），
Cache 数据阵列按行存储（单写端口），一次读回整行，缺失代价 5 拍 → 3 拍，
BRAM 30 块、LUT 7828。

**下一步增强**：

| 项目 | 建议值 | 收益 |
|---|---|---|
| 两路组相联 + 伪 LRU | 2 KB/路，16 B/line | 消除直接映射的冲突缺失 |
| 关键块优先 (critical-word-first) | 先返回请求字，其余 3 字后台填充 | 缺失代价 5 拍 → 2 拍 |
| 非阻塞填充 | 填充期间允许命中的取指继续 | 进一步隐藏缺失 |
| 写回 (write-back) + 脏位 | 降低 store 的存储器写带宽 | CoreMark 写密集场景 |
| 数据阵列 BRAM 化 | 2 KB x 2 路 = 1 个 BRAM36 | 释放 LUTRAM，利于布线与频率 |

**预期收益**：CoreMark 的 CPI 中存储器停顿再降 30%～50%，配合 BTB 可到 1.5+ IPC。

## 阶段 4：CoreMark 移植与性能评估（已完成）

- 工具链：`riscv-none-elf-gcc 14.2.0`（xPack），`-march=rv32im_zicsr -O2`
- 裸机环境：`sw/c/crt0.S` + `link.ld` + `uart.c`（printf → UART）
- CoreMark 2K performance run **CRC 全部匹配官方值**，1 次迭代计时区
  350,915 拍，折算 **≈2.85 CoreMark/MHz**
- 复现：`sw/c/build_coremark.ps1` + `vvp sim.vvp +UART`

**后续可做**：多次迭代取平均（仿真较慢）、把 `mcycle` 采样点放进 CoreMark
计时区以排除启动开销、在 PGL22G 上跑 ≥10 秒的有效成绩。

**对照基线**：当前 5 级流水 + 2 KB 两路 Cache + BTB + M 扩展，
自测 IPC 约 0.35～0.98（依负载而定），CoreMark 目标 1.2～1.5 CoreMark/MHz。

## 阶段 5：紫光同创 PGL22G 板级工程

1. PDS 新建工程，器件选 PGL22G-6MBG324（以实际板卡为准）。
2. 用 `rtl/soc/fpga_top.v` 作为顶层：时钟、复位、UART、LED、按键。
3. 生成 PLL IP（50 MHz → 100 MHz），替换 `fpga_top` 内的直连时钟。
4. 把 `imem.hex`/`dmem.hex` 转成 PDS BRAM 初始化文件（.mif 或 `$readmemh`）。
5. 引脚约束：`constraints/pango_pins.fdc`（模板已给出，按板卡引脚表填写）。
6. 时序约束：`create_clock -period 10 [get_ports clk]`，先跑 100 MHz，
   根据 `report_timing` 迭代（主要瓶颈在 EX 级分支/转发路径，频率目标 100 MHz）。

## 阶段 6：AI 加速（基础版已完成）

已完成：8 KB 缓冲 + INT8 FC/RELU/ARGMAX 加速器，MNIST 196-32-10 MLP 跑通，
仿真 19/20。后续可做：脉动阵列（8x8）、卷积模式、DMA 搬运、量化工具链自动化。

### 原始规划（保留）

赛题高级任务要求"在 RISC-V 核上扩展 AI 加速单元（矩阵/卷积/激活）"。

**建议路线**

- 自定义指令（custom-0 opcode `0001011`）：`macc`（4×8bit 点积）、`relu`、`max`。
- 在 EX 级挂一个 4×4 的 systolic 阵列（INT8），通过 CSR 配置行列数。
- 数据通路：DMA 从 DMEM 搬到本地 SRAM，计算完成后写回。
- 软件侧：提供 `accel.h` 内联汇编封装 + 一个 3×3 卷积 demo。

---

## 阶段 7：频率修复（已完成第一步）

已把乘法器移到 MEM 级：EX 只做转发/分支，乘法用 EX/MEM 寄存器里的操作数计算，
依赖指令停顿 1 拍经 MEM/WB 转发。WNS 从 -6.06 ns 改善到 -2.15 ns，
逻辑延迟 10.3 ns → 4.1 ns。

**进一步**：使用带 AREG/BREG + MREG 的 DSP 乘法器（2 拍延迟、每段短），
或把 32x32 拆成 17x17 分块流水，可把剩余路径继续压到 10 ns 以内。

## 工程约定（避免重复踩坑）

1. Verilog 源文件 **禁止 UTF-8 BOM**（iverilog 会静默丢弃文件内容）。
2. 每个 RTL 文件首行加 `` `timescale 1ns/1ps ``（Vivado xsim 要求全设计一致）。
3. 新增指令/CSR 必须同步更新 `sw/tools/rvasm.py` 与自检测试。
4. 每次改动后跑 `sim/run.ps1 -Rebuild` 全回归，并用 `run_xsim.ps1` 抽查。
