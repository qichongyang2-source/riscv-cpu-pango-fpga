## 2. 流水线寄存器

| 级间寄存器 | 主要内容 |
|---|---|
| IF/ID | `pc, instr, valid` |
| ID/EX | `pc, instr, rs1/rs2 数据与编号, imm, ALU 控制, 访存控制, 写回选择, 分支/跳转类型, CSR 控制, 异常信息, valid` |
| EX/MEM | `pc, instr, ALU 结果, 存储数据, rd, 写回选择, funct3, CSR 写端口, 异常信息, mret 标志, valid` |
| MEM/WB | `pc, instr, 写回数据, rd, reg_write, valid` |

## 3. 数据冒险处理

### 3.1 转发（EX 级）

- `EX/MEM → EX`：上一拍 ALU 结果（load 除外，因为数据要到 MEM 末尾才有效）
- `MEM/WB → EX`：写回数据
- `WB → ID`：寄存器堆同拍写读旁路，解决相距 3 条指令的 RAW

优先级：EX/MEM > MEM/WB > 寄存器堆。

### 3.2 load-use 停顿

```
lw   t0, 0(a0)
add  t1, t0, t0     ← 检测到 ID 源寄存器 == EX 级 load 的 rd
```

停顿 1 拍：冻结 PC 与 IF/ID，向 ID/EX 插入气泡；下一拍改由 MEM/WB 转发。

### 3.3 CSR 写后读互锁

`csrw` 在 MEM 级提交，紧随其后的 `csrr` 若已进入 EX 会读到旧值，因此让 `csrr`
在 ID 级多停 1 拍。该行为是 RISC-V 允许的实现定义行为，本设计选择"互锁"以获得
更友好的编程模型。

## 4. 控制冒险

- 静态预测：**不跳转**（分支）／顺序执行。
- 分支、JAL、JALR 均在 **EX 级** 解析，目标地址由转发后的操作数计算。
- 跳转成立时：`IF/ID`、`ID/EX` 清空，PC 取目标地址 ⇒ 代价 **2 拍**。
- 跳转目标非 4 字节对齐 ⇒ 触发指令地址非对齐异常（`mcause=0`）。

后续优化方向：把分支比较前移到 ID 级（需增加 ID 级比较器与专用转发），
或增加 BTB + 两位饱和计数器，把代价降到 0～1 拍。

## 5. 异常与中断

### 5.1 异常来源

| 异常 | mcause | 说明 |
|---|---|---|
| 指令地址非对齐 | 0 | 跳转目标 `[1:0] != 0` |
| 非法指令 | 2 | 译码不合法 |
| EBREAK | 3 | 断点 |
| Load 地址非对齐 | 4 | LW/LH 未按自然对齐（`mtval` = 地址） |
| Store 地址非对齐 | 6 | SW/SH 未按自然对齐（`mtval` = 地址） |
| ECALL (M) | 11 | 系统调用 |

异常在 **MEM 级** 统一提交：冲刷 IF/ID、ID/EX、EX/MEM，抑制该指令的寄存器写、
存储器写与 CSR 写，保证精确异常。

### 5.2 中断

- `timer` 外设比较 `mtime >= mtimecmp` 产生 MTIP（bit7）。
- 外部中断输入（板级 `irq_ext_i` 或软件中断寄存器 `0x2000_3000`）产生 MEIP（bit11），
  优先级高于 MTIP。
- `irq_pending = mstatus.MIE & (mie & mip)`；`irq_cause` 由优先级编码给出（11 或 7）。
- mtvec 支持直接/向量两种模式：`mtvec[1:0]==1` 时中断入口 = base + 4*cause，
  同步异常仍进 base。
- 在 MEM 级、且当前指令无异常时响应；`mepc` 保存被中断指令地址，`mret` 后重新执行。

### 5.3 WFI

`WFI` 的译码结果为 NOP（RISC-V 允许将 WFI 实现为 NOP），不影响流水线。

### 5.4 陷入/返回时序

```
trap:  mepc <- epc;  mcause <- cause;  mtval <- tval
       MPIE <- MIE;  MIE <- 0;  MPP <- 3
       PC   <- mtvec
mret:  MIE <- MPIE;  MPIE <- 1;  MPP <- 0
       PC  <- mepc
```

## 6. 存储接口

- IMEM/DMEM 为 **128 位宽（4096 x 128）** 的 BRAM 风格存储器：一次读回整行 16 B；
  写为 32 位 + 16 路字节使能（把 4 位 BE 平移到目标通道），单读端口 + 单写端口。
- 内核通过 I/D-Cache 访问主存，Cache 命中为组合读（LUTRAM），缺失时由填充状态机
  以整行突发方式访问主存。
- DMEM 支持字节使能，`riscv_lsu` 完成：
  - 写：按 `funct3` + `addr[1:0]` 生成 `be` 与按字节铺开的写数据；
  - 读：按 `funct3` 选择字节/半字并做符号/零扩展。
- 非对齐访问由多字节通道组合完成，不产生异常（RISC-V 允许）。

> 上板时 64 KB 主存映射为 BRAM，由 2 KB 的 LUTRAM Cache 提供零等待命中的
> 取指/数据带宽；Cache 缺失时冻结流水线并整行填充。

## 7. Cache 子系统

### 7.1 结构

| 项目 | I-Cache | D-Cache |
|---|---|---|
| 容量 | 2 KB | 2 KB |
| 组织 | 64 组 x 2 路 x 4 字（16 B/行），伪 LRU | 同左 |
| 索引/标记 | set = addr[9:4]，tag = addr[31:10] | 同左 |
| 命中 | 组合读（LUTRAM），零等待 | 同左 |
| 缺失 | 128 位整行突发，3 拍完成，冻结 IF | 128 位整行突发，3 拍完成，冻结流水线 |
| 写策略 | — | 写穿 + 不写分配；写命中同时更新行与存储器 |
| 缺失代价 | 3 拍 | 3 拍 |

```
IF ──pc──▶ I-Cache ──hit──▶ 指令
              │miss
              ▼
         fill FSM ──▶ IMEM（同步读，1 拍）
```

### 7.2 填充时序

```
S_IDLE : 检测缺失，清 valid（逐出），发出整行读（128 位）
S_CAP  : 一拍把整行写入数据阵列（按行存储，单写端口），写 tag/valid
S_DONE : 命中通路生效，释放 stall
```

两路组相联：逐出时优先选择空路，否则选择 LRU 路；命中后更新 LRU 位。
相比直接映射，消除了"两个相隔 2 KB 的数组互相逐出"这类冲突缺失。

`stall = !hit`：只要当前地址不在 Cache 中，就冻结相关流水级；
行填充期间先清 `valid`，避免部分写入被误命中。

### 7.3 与内核的配合

- **I-Cache 缺失**（`if_stall`）：PC 保持、IF/ID 插入气泡、ID/EX 继续排空。
- **D-Cache 缺失**（`mem_stall`）：PC、IF/ID、ID/EX、EX/MEM、MEM/WB 全部保持，
  同时抑制 DMEM/CSR 写与提交计数，避免重复副作用。
- 外设（UART/GPIO/TIMER）与测试寄存器**不经过 D-Cache**，由地址译码旁路。

### 7.4 存储器

IMEM/DMEM 改为 BRAM 风格同步读（地址打一拍），由 Cache 填充；写为同步写。
这样 64 KB 存储器可以映射到 BRAM，而 Cache 只用小容量 LUTRAM，兼顾频率与容量。

## 7b. 分支预测（BTB + 两位饱和计数器）

| 项目 | 实现 |
|---|---|
| BTB | 64 项，index = pc[7:2]，tag = pc[31:8]，表项 {valid, target} |
| BHT | 64 个两位饱和计数器（00/01 预测不跳，10/11 预测跳） |
| 预测 | 表项有效 + tag 命中 + 计数器 ≥ 2 ⇒ 下一 PC 取 target |
| 训练 | EX 级解析后写 BTB，跳转则 +1，不跳转则 -1 |
| 预测失败 | 方向或目标不符 ⇒ 冲刷 IF/ID、ID/EX，PC 取正确目标（2 拍惩罚） |
| 特殊 | "预测跳转但指令不是控制指令"同样按失败处理，回到 pc+4 |

预测正确时**不冲刷流水线**，循环中的后向分支从第 2 次迭代起零惩罚。
测试中 t08 的等待循环 IPC 由 0.59 提升到 0.98，t10 由 0.72 提升到 0.91。

## 7c. M 扩展（乘除法）

| 运算 | 实现 | 延迟 |
|---|---|---|
| MUL / MULH / MULHSU / MULHU | 在 **MEM 级**用已寄存的 EX/MEM 操作数计算 | 1 拍（依赖指令再停 1 拍） |
| DIV / DIVU / REM / REMU | 恢复余数迭代，32 次移位-比较-减法 | 32 拍 |

乘法器放在 MEM 级而不是 EX 级，是为了把"转发 mux → 乘法 → 写回 mux"这条长路径
拆开：EX 级只负责分支/目标计算，乘法器输入直接来自 EX/MEM 寄存器。
代价是乘结果在 MEM 末尾才有效，因此依赖指令按 load-use 同样的方式停顿 1 拍，
并由 MEM/WB 转发。

- 译码：`funct7 = 0000001` 识别为 M 扩展，`funct3` 选择具体运算。
- 除法期间 `div_freeze` 冻结整条流水线（PC/各级寄存器保持），
  `done` 单拍给出结果；遇到 trap/mret 时中止运算（`flush`）。
- 除零、`-2^31 / -1` 溢出按 RISC-V 规范处理（商 = -1 / -2^31，余数 = 被除数 / 0）。
- 副作用（DMEM 写、CSR 写、提交计数）统一由 `pipe_freeze` 抑制，避免冻结期间重复执行。

## 7d. AI 加速器

| 项目 | 实现 |
|---|---|
| 接口 | memory-mapped：`0x2000_4000` 控制寄存器，`0x2000_8000-9FFF` 8 KB 缓冲 |
| 算子 | `FC`（INT8 x INT8 -> INT32，4 路并行）、`RELU`（原地）、`ARGMAX` |
| 数据布局 | W 为 K x 4 行优先（每 4 个输出一组），x 为 K 个 INT8，y 为 4 个 INT32 |
| 控制 | CTRL/OP/K/N/WA/XA/YA + busy/done + 周期计数 + argmax 结果 |
| 偏置 | 折进 W 的额外一行（x 末尾置 1），不占硬件 |
| 缓冲 | 2048 x 32，异步读，CPU 与引擎分时复用端口 |

数据流（推理一帧）：

```
CPU: 图像/权重 -> AI 缓冲（sw）
     -> FC(196x4) x 8 组 -> 偏置+ReLU+定点缩放（CPU）
     -> FC(32x4) x 3 组 -> 偏置 -> ARGMAX（硬件）-> 类别
```

- MNIST 196-32-10 MLP：权重 6.7 KB、激活 128 B，全部驻留 8 KB 缓冲。
- 量化：per-tensor 对称量化 + 校准集激活缩放（M/2^15），
  Python 仿真 96.19%，RTL 仿真 19/20（95%）。

## 8. 关键参数与常量

- `RESET_VEC = 0x0000_0000`，`MTVEC_INIT = 0x0000_0040`
- 时钟：仿真 50 MHz；上板目标 100 MHz（存储器已 BRAM 化，主要瓶颈在 EX 级分支/转发路径）
- 复位：低有效同步复位（`rst_n`）
