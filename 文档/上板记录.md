# 上板记录（FPGA LAB 远程实验箱）

> 首次尝试：2025-11-04，设备「实验箱8」，租期 30 分钟。
> 结论：平台链路已摸清，板级设计在 27 MHz 仿真下跑通；因时间用尽未完成烧录验证。

## 一、板卡档案（平台内置 DUT）

| 项目 | 内容 |
|---|---|
| FPGA | Pango **PG2L200H**（Logos2，FBB676） |
| 约束格式 | `.fdc`（由平台按档案生成，不手写） |
| 板卡构成 | 主 DUT + 双子卡（S2 点阵/RGB，S3 交通灯/数码管/按键/LED） |
| 时钟 | `clk` = **D18**，**27 MHz**（周期 37.037 ns） |
| 复位 | `rst_n` = C22，低有效（**远程平台可能长期为低，默认不用**） |
| LED | `LED[0..3]` = U16 / U15 / V17 / V16，**低电平点亮** |
| 串口 | `uart_tx` = AB26，`uart_rx` = AC26，115200 8N1 |
| 按键 | `KEY[0..3]` = U21 / W24 / V24 / AA23，低电平按下 |

约束方式（交给平台，不手写厂商语法）：

```text
project_set_pin_constraints(signals="clk,rst_n,LED,uart_tx,uart_rx,KEY")
```

时钟约束另加：37.037 ns。总线只给基名，平台自动展开；端口名必须与 RTL 顶层逐字一致。

## 二、平台操作流程

1. 工作区 → 新建工程 → 「源文件 +」上传 `.v`
2. 左上「顶层」选 `fpga_top`
3. 「约束 +」→ 用上面的函数生成引脚约束 + 时钟约束
4. 「编译」→ 看「诊断 / 资源占用 / 时序」
5. 「烧录」→ 上传 `.sbit` 或直接下载
6. 左侧「串口通信」看输出（115200 8N1）

## 三、上板版本的生成方式

单文件版本（含程序初值）：

```powershell
cd 代码
python sw/tools/rvasm.py sw/tests/hello.s -o sim/work     # 生成 imem.hex / dmem.hex
python sw/tools/flatten.py -o rtl_flat/riscv_soc_board.v ^
       --init-imem sim/work/imem.hex --init-dmem sim/work/dmem.hex
```

产物：`代码/rtl_flat/riscv_soc_board.v`（约 2700 行，含 BRAM 初值）。

板级仿真验证：

```powershell
iverilog -g2012 -s tb_board -o sim/work/board.vvp rtl_flat/riscv_soc_board.v tb/tb_board.v
cd sim/work; vvp board.vvp
# 预期：UART chars = 25、LED = 0011、BOARD SIM PASSED
```

## 四、本轮发现并修复的问题

| 问题 | 根因 | 修复 |
|---|---|---|
| PDS 综合报错（单 for 展开 > 2000） | `imem/dmem` 在综合路径上做 4096 次全阵列清零 | 清零循环移入 `ifdef SIM_INIT`；综合靠 `initial` 初值 |
| 仿真中整机不启动 | POR 计数器无初值，仿真为 X → 一直复位 | `por_cnt`/`por_n` 显式初值 |
| 串口持续打印乱码 | 只注入了 imem，`.data` 段（dmem）未初始化 | flatten 增加 `--init-dmem` |
| 虚拟按键“点了没反应” | 孪生端按键走边界扫描，电平直通采不到 | 5 ms 消抖 + 下降沿翻转锁存（已实现） |
